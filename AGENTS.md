# AGENTS.md

This file provides guidance to AI coding agents working with code in this repository.

## Commands

Development uses a virtual environment in `.venv` (pyright is configured to use it). Install with `pip install -e .[dev]`.

- Lint and format: `pre-commit run --all-files`
- Type check: `pyright`
- Run the tests (require gcc): `pytest`
- Run a comparison with PLECS (requires PLECS Standalone with the RPC interface on port 1080): `python examples/ipmsm_2kw_fvc.py`
- Run a comparison with Simulink (requires MATLAB with a MinGW-w64, gcc, or clang compiler for `mex` and the MATLAB Engine API for Python matching the MATLAB release): `python examples/ipmsm_2kw_fvc_simulink.py`

## Architecture

- `motulator_export/plecs/sm.py`, `im.py`, and `grid.py` write PLECS models of synchronous machine drives, induction machine drives, and grid converter systems. Each provides `write_model` and `simulate`, and `export_values` gets the parameters of the control system in the *motulator* API. The shared building blocks are in `_schematic.py` (the PLECS file format: the schematic writer `_Schematic`, probes, scopes, masks, and C-Script parameters), `_common.py` (the step signals, the control-system block `ControlBlock`, the converter, the DC bus, and the model file), `_drive.py` (the mechanics, the speed controller values, and the scope), and `_rpc.py` (the simulation via the RPC interface). The package `motulator_export` exports `StepSignal` and `sampled_step`, which both exports use.
- In the control systems, each class of *motulator* is a block with a mask of the arguments of its class, in the hierarchy of *motulator*. They are described as netlists (`plecs/_netlist.py`: C blocks, selectors, multiplexers, tags, and subsystems with their connections, masks, and layout hints) in `plecs/_sm_control.py`, `_im_control.py`, `_im_vhz_control.py`, and `_grid_control.py`, with the common classes (`PWM`, `SpeedController`, `SpeedObserver`, `CurrentLimiter`, `RateLimiter`) and the top levels (`VectorControlSystem`, `VHzControlSystem`, `GridConverterControlSystem`) in `plecs/_control.py`. The masks of the composite classes compute the arguments of the blocks inside them in their initialization (MATLAB syntax, also run by PLECS), as the constructors of *motulator* do, and the masks of the top-level classes refer to the structs (e.g., `par`, `cfg`, `speed_ctrl`, and `pwm`) of the model initialization (`init_script` of the control modules: the initialization commands of PLECS, and `init_<model>.m` of Simulink, run by the model after loading and at the start of each simulation). The C blocks initialize their states from their own parameters (copying the parameters used later, since the parameters are read only in the start function), and the signal vectors (meas, fbk, ref) are defined in the C headers of the control methods (`Signals` in `_control.py`). The first input of the stateful blocks and of the control system is `enable` (`block_enable_code` in `_common.py`): while it is not positive, the duty ratios are 0.5 and the states are reset to their initial values. The layout engine of `_netlist.py` places the blocks and routes the wires for both tools (`PLECS` and `SIMULINK` geometries), and `problems` checks for crossings; use `_netlist.preview` to draw a layout when changing the hints. `plecs/_render.py` renders a netlist in PLECS and `simulink/_render.py` with `+blocks/add_netlist.m` in Simulink.
- `motulator_export/c/` is the C port of the *motulator* control algorithms, run in the C-Script blocks of PLECS and the S-functions of Simulink. It follows the Python code of *motulator* closely, including the order of the state updates, and the tests in `tests/` compare it with *motulator* step by step (the C test APIs are compiled with the helpers in `tests/c_port.py`). A change in the control algorithms of *motulator* must be mirrored here. The tests pass NaN for the optional parameters so that the default values are resolved in C, as in *motulator*. The whole-system functions (e.g., `vector_control_system_compute_output`) are used by the monolithic reference control systems of the tests.
- `motulator_export/simulink/` writes Simulink models (`sm.py`, `im.py`, `grid.py`). The blocks of the classes are the C-Script code of the PLECS model wrapped in generated C MEX S-functions (`_sfunction.py`), and the models are built in MATLAB by `build_drive.m` and `build_grid.m` with the common parts in the package `+blocks`. On Windows, the tests can use the MinGW-w64 gcc of MATLAB (on the PATH).
- Tests of the control systems: `tests/monolithic.py` defines each control system as one C-Script block running the whole-system functions of the C port, `tests/test_simulink.py` compares their S-functions with *motulator* in closed-loop simulations with a mock of the Simulink API (`tests/simulink_mock`), and `tests/test_control.py` executes the netlists with the S-functions of the blocks (`tests/netlist.py`, as Simulink does), with the parameters computed from the model initialization through the masks by an interpreter of the MATLAB subset (`tests/matlab.py`), compares them with *motulator*, checks that the results equal those of the monolithic control systems exactly, and checks the layouts for crossings.
- `examples/` contains the comparison scripts and the generated models (the Simulink build and initialization scripts and the S-function sources in `examples/simulink/`). Regenerate the models by running the scripts after changing the writers, and check that the differences stay at the level recorded in `examples/README.md` and `motulator_export/simulink/README.md` (update the tables if they change). `examples/screenshots.py` remakes the screenshots of the README and their dark versions.

## Conventions

- Follow the conventions of *motulator*: peak-valued complex space vectors, SI units, NumPy-style docstrings, and line length 88.
- PLECS: the schematic coordinates are chosen so that wires do not cross and the labels are below the blocks (in the control systems, by the layout hints of the netlists). Only the signals fed back to the control system are measured with meters; the other signals use PLECS probes.
- Simulink: the blocks are aligned with the ports they connect to (`blocks.align`), so that the lines are straight, and the feedback lines are drawn through given corners (`blocks.route`).
