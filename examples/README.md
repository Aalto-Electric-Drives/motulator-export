# Examples

Each script builds a system of a *motulator* example, writes the PLECS model (`*.plecs` in this directory), and, if PLECS Standalone is running with the RPC interface enabled, simulates the system in both *motulator* and PLECS and prints the maximum differences.
The scripts `*_simulink.py` do the same for Simulink, writing the scripts `simulink/build_*.m`, which build the systems with the MATLAB classes of *motulator* and the models from the blocks of its Simulink library; see [the Simulink export](../motulator_export/simulink/README.md).
With `--matlab`, the blocks of the control system are MATLAB Function blocks running the MATLAB port of the control algorithms instead of S-functions (the models `simulink/*_matlab.slx`), which need no C compiler.
The structure of the PLECS models and their agreement with *motulator* are described in [the PLECS export](../motulator_export/plecs/README.md).

| Script                    | System                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ipmsm_2kw_fvc.py`        | 2.2-kW IPMSM, sensorless flux-vector control (the README example of *motulator*); with `--diode`, a diode bridge with a DC-bus inductor and capacitor; with `--blocked`, the gates blocked before the start and under the load, the control system running in standby (as in `plot_2kw_ipmsm_blocked_cvc.py`)                             |
| `ipmsm_2kw_cvc.py`        | 2.2-kW IPMSM, sensorless current-vector control (`plot_2kw_ipmsm_blocked_cvc.py`); with `--blocked`, the gates blocked before the start and during the operation, as in the example, with the flying start after the release; with `--discrete`, the direct discrete-time current controller (`discrete=True`)                            |
| `ipmsm_2kw_vhz.py`        | 2.2-kW IPMSM, observer-based V/Hz control (`plot_2kw_ipmsm_ovhz.py`, with the speed reference stepped and rate-limited instead of ramped)                                                                                                                                                                                                 |
| `pmsyrm_6kw_gn_fvc.py`    | 5.6-kW PM-SyRM, GradNet models from FEM data (in `trained_models/`), sensored flux-vector control (`plot_6kw_pmsyrm_gn_fvc_fem_harm.py`)                                                                                                                                                                                                  |
| `im_2kw_cvc.py`           | 2.2-kW induction machine, sensorless current-vector control (`plot_2kw_im_sat_cvc.py` with the constant-parameter machine model)                                                                                                                                                                                                          |
| `im_2kw_dead_time_cvc.py` | 2.2-kW induction machine, dead time and threshold voltage and their compensation, single update, sensorless current-vector control at low speeds (`plot_2kw_im_dead_time_cvc.py` with the constant-parameter machine model and `sign=np.sign`); with `--tanh`, the compensation uses `sign=tanh(i/i_0)`                                   |
| `im_2kw_vhz.py`           | 2.2-kW induction machine, observer-based V/Hz control (`plot_2kw_im_ovhz.py`); with `--open-loop`, pure open-loop V/Hz control, i.e., the observer-based V/Hz controller with the machine model `L_M = inf` (and `R_s = R_R = L_sgm = 0`) and zero gains, as in `plot_2kw_im_diode_vhz.py` (with a stiff DC bus and without the friction) |
| `gfl_10kva_lcl.py`        | 10-kVA grid converter with an LCL filter, grid-following control (`plot_10kva_lcl_gfl.py`)                                                                                                                                                                                                                                                |
| `gfm_13kva_do.py`         | 12.5-kVA grid converter with an L filter in a weak grid, disturbance-observer-based grid-forming control (`plot_13kva_do_gfm.py`)                                                                                                                                                                                                         |

The examples of the native simulation (`motulator_export.native`) are in `native/`.

Run the scripts from the repository root, e.g., `python examples/ipmsm_2kw_fvc.py`.
For the comparison, a script writes a temporary copy of the model (`*_tmp.plecs`, removed at exit) with output ports, through which the RPC interface returns the signals; the models in this directory have no output ports.
The scripts close the model in PLECS before simulating it, since an open model is not reloaded from the file.
The code shared by the scripts (the simulation of *motulator* with the tolerances of 1e-9, the output times at the solver steps and just after the sampling instants, the maximum differences, and the plots) is in `_compare.py`.

## Screenshots

`screenshots.py` makes the Simulink screenshot of the documentation (`docs/source/images/`): it prints the Simulink model of `pmsyrm_6kw_gn_fvc_simulink.py` with the MATLAB Engine API.
The PLECS screenshots are exported from PLECS: the schematics with File > Export schematic (300 dpi), the scope of `ipmsm_2kw_fvc.plecs` after the simulation with File > Export > as Bitmap of the scope window (160 mm × 150 mm, without the legend, with antialiasing), and the mask dialog of the `SpeedController` block as a screen capture.
With `--dark`, the script writes the dark versions of all the screenshots (`*_black.png`, the lightness inverted and the hues kept).
