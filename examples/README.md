# Examples

Each script builds a system of a *motulator* example, writes the PLECS model (`*.plecs` in this directory), and, if PLECS Standalone is running with the RPC interface enabled, simulates the system in both *motulator* and PLECS and prints the maximum differences.
The scripts `*_simulink.py` do the same for Simulink, writing the build and initialization scripts of the models in `simulink/`; see [the Simulink export](../motulator_export/simulink/README.md).
With `--matlab`, the blocks of the control system are MATLAB Function blocks running the MATLAB port of the control algorithms instead of S-functions (the models `simulink/*_matlab.slx`), which need no C compiler.

| Script                    | System                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ipmsm_2kw_fvc.py`        | 2.2-kW IPMSM, sensorless flux-vector control (the README example of *motulator*); with `--diode`, a diode bridge with a DC-bus inductor and capacitor; with `--blocked`, the gates blocked before the start and under the load, the control system running in standby (as in `plot_2kw_ipmsm_blocked_cvc.py`)                             |
| `pmsyrm_6kw_gn_fvc.py`    | 5.6-kW PM-SyRM, GradNet models from FEM data (in `trained_models/`), sensored flux-vector control (`plot_6kw_pmsyrm_gn_fvc_fem_harm.py`)                                                                                                                                                                                                  |
| `im_2kw_cvc.py`           | 2.2-kW induction machine, sensorless current-vector control (`plot_2kw_im_sat_cvc.py` with the constant-parameter machine model)                                                                                                                                                                                                          |
| `im_2kw_dead_time_cvc.py` | 2.2-kW induction machine, dead time and threshold voltage and their compensation, single update, sensorless current-vector control at low speeds (`plot_2kw_im_dead_time_cvc.py` with the constant-parameter machine model and `sign=np.sign`); with `--tanh`, the compensation uses `sign=tanh(i/i_0)`                                   |
| `im_2kw_vhz.py`           | 2.2-kW induction machine, observer-based V/Hz control (`plot_2kw_im_ovhz.py`); with `--open-loop`, pure open-loop V/Hz control, i.e., the observer-based V/Hz controller with the machine model `L_M = inf` (and `R_s = R_R = L_sgm = 0`) and zero gains, as in `plot_2kw_im_diode_vhz.py` (with a stiff DC bus and without the friction) |
| `gfl_10kva_lcl.py`        | 10-kVA grid converter with an LCL filter, grid-following control (`plot_10kva_lcl_gfl.py`)                                                                                                                                                                                                                                                |
| `gfm_13kva_do.py`         | 12.5-kVA grid converter with an L filter in a weak grid, disturbance-observer-based grid-forming control (`plot_13kva_do_gfm.py`)                                                                                                                                                                                                         |

The examples of the native simulation (`motulator_export.native`) are in `native/`.

Run the scripts from the repository root, e.g., `python examples/ipmsm_2kw_fvc.py`.
For the comparison, a script writes a temporary copy of the model (`*_tmp.plecs`, removed at exit) with output ports, through which the RPC interface returns the signals; the models in this directory have no output ports.
The scripts close the model in PLECS before simulating it, since an open model is not reloaded from the file.

`screenshots.py` makes the Simulink screenshot of the README: it prints the Simulink model of `pmsyrm_6kw_gn_fvc_simulink.py` with the MATLAB Engine API and writes its dark version (`*_black.png`, the lightness inverted and the hues kept). The PLECS screenshots `pmsyrm_6kw_gn_fvc.png` and `pmsyrm_6kw_gn_fvc_black.png` are exported from PLECS (File > Export > PNG, 300 dpi) with the light and the dark theme of PLECS.

## Structure of the PLECS models

- The references (e.g., the speed reference or the power references) and the load torque are Step blocks; several steps are given as vector parameters of one Step block and summed by a Gain block. A constant reference (the converter voltage reference of grid-forming control) is a Constant block.
- The first input of the control system is `enable`, the gate enable of the control system of *motulator* (`ctrl.set_enable`): a Constant block of 1 by default, or a Step block. While it is zero, the gates are blocked, and the control system runs in standby as in *motulator*, see [the README](../README.md). The tag `enable` also takes the input to the gates of the converter (see below). The control system limits the measured DC-bus voltage to at least 1 V.
- The control system contains a block for each class of *motulator*, in the hierarchy of *motulator*. Each block of a class is a masked subsystem with the arguments of its class, containing a C-Script block that runs the C code of the class:
  - Flux-vector control: `VectorControlSystem` (the masked subsystem) contains the measurements (`get_measurement`), the `PWM` (a subsystem with `compute_output` and `get_realized_voltage`), the `SpeedController`, the `FluxVectorController`, `modulate` (the voltage reference in stationary coordinates, its angle advanced by `k_comp*T_s*w_c` with `k_comp = 1.5` of the controller), and the monitored signals. The `FluxVectorController` contains the `ReferenceGenerator`, the `FluxTorqueController`, and the `SpeedFluxObserver`, which contains the `SpeedObserver` and the `FluxObserver`.
  - Current-vector control: the `CurrentVectorController` contains the `CurrentReferenceGenerator`, the `CurrentController`, and the `SpeedFluxObserver`.
  - V/Hz control: `VHzControlSystem` contains the `RateLimiter` of the speed reference instead of the speed controller, and the `ObserverBasedVHzController` contains the `FluxObserver` (without speed estimation, the rotor speed being the rate-limited speed reference), the `ReferenceGenerator`, the `FluxTorqueController`, and the low-pass filter of the torque estimate (`tau_M_lpf`). Pure open-loop V/Hz control is the special case `par.L_M = inf`, for which the mask initialization of the `ObserverBasedVHzController` sets the unit observer gain and the other settings, as *motulator* does.
  - Grid-following control: the `CurrentVectorController` of `GridConverterControlSystem` contains the `PLL`, the `CurrentController`, and its `compute_output` before and after the `CurrentLimiter` (the current reference from the power references, and the power references corresponding to the limited current reference, `power_reference`).
  - Grid-forming control: the `ObserverBasedGridFormingController` contains the `Observer` (designed in discrete time), the `PowerReferenceLimiter` (no limitation without `cfg.i_d_max`), and its `compute_output` before and after the `CurrentLimiter` (the current reference from the limited active-power reference, and the voltage reference).
- The masks of the composite classes pass the arguments to the blocks inside them as the constructors of *motulator*, e.g., the mask initialization of the `FluxVectorController` resolves the defaults of `FluxVectorController`, and that of the `SpeedFluxObserver` resolves the defaults of `create_speed_flux_observer` and computes the gains of `SpeedFluxObserver` (with the speed estimation poles matched to the sampling period). The masks of the top-level classes refer to the variables defined in the initialization commands of the model, which read as the *motulator* example (`[]` is `None`): `par` (the machine model), `cfg` (the configuration of the controller), `speed_ctrl` (`SpeedController`) or `slew_rate` (of `VHzControlSystem`), and `pwm` (the PWM). The mask of the control system passes these variables to the blocks inside it as its parameters, since the blocks inside a masked subsystem of PLECS see only the variables of its mask; `T_s` of the mask of the control system and of the delay and the PWM is `cfg.T_s`.
- The measurements, the feedback signals, and the references are signal vectors (`meas`, `fbk`, and `ref`, defined in the C headers, e.g., `motulator_export/c/sm_flux_vector.h`), whose fields are selected by Signal Selector blocks (e.g., `fbk.w_M`) where *motulator* accesses them. The input `enable` is distributed by Goto and From blocks, as are the feedback signals and the references to the speed controller and to the monitored signals, the voltage reference fed back to the field weakening and to the active-power limitation, and the current to the active-power limitation.
- The control system samples the references and the measurements (e.g., the phase currents, the DC-bus voltage, and the rotor angle or speed in the sensored mode) with the sampling period `T_s`. The duty ratios pass through a Delay block, which models the computational delay of one sampling period, as in *motulator*.
- The Symmetrical PWM block of PLECS (regular sampling with double update, carrier frequency `1/(2*T_s)`) generates the gate signals of the IGBT converter of PLECS with ideal IGBTs and diodes, which are multiplied by the gate enable sampled at the sampling instants (a Zero-Order Hold block), as the control system of *motulator* evaluates the gate enable. While it is zero, the gate signals are zero, i.e., the switches are off, and the current directions determine the conducting diodes, as in *motulator*. The line-to-line converter voltages u_ab and u_bc, used by the control system while the gates are blocked, are measured with voltmeters between the phase lines. This corresponds to carrier comparison in *motulator* (`pwm=True`), except that the counter quantization of the duty ratios is not modeled. With single update (`single_update=True` and `delay=2` in *motulator*, i.e., the computational delay of one sampling period), the carrier frequency is `1/T_s`, and the delayed duty ratios change only at the maxima of the carrier, so the sampling also at its minima gives the single update. The scripts therefore use a fine quantization in *motulator* (`CarrierComparison(N=2**24)`); with the default quantization of 4096 levels, the differences are about 1e-2.
- With the dead time of the converter (`t_d`, drives only), the Blanking Time block of PLECS delays the turn-on of the switches by `t_d`, and the converter is the IGBT converter of PLECS with ideal IGBTs and diodes: during blanking, both switches of the leg are off, and the current direction determines the conducting diode, as in *motulator* with `sign=np.sign`. With the threshold voltage of the power devices (`u_th`, drives only), the converter is the IGBT converter with parasitics of PLECS, whose forward voltages of the IGBTs and the diodes are `converter.u_th` (without on-resistances), so that the conducting device reduces the phase voltage by `u_th*sign(i)`, as in *motulator*. The duty-ratio error model of the PWM of the control system (`d_err = InverterNonlinearity(t_d, u_th, sign)`) is given by the dead time `pwm.t_d`, the threshold voltage `pwm.u_th`, and the current scale `pwm.i_0` of the initialization commands (no error model if `t_d = u_th = 0`), and the compensation can be disabled (`pwm.feedforward = 0`). The minimum duty ratio of a switching leg (`PWM(d_min=...)`), the single update (`PWM(single_update=True)`, which halves the half carrier period of the error model), and the overmodulation (`'MPE'`, or `'MME'` as in V/Hz control) are also parameters of the PWM (`pwm.d_min`, `pwm.single_update`, and `pwm.overmodulation`). The current direction in the control system is `sign = np.sign` (`i_0 = 0`, by default in the examples) or the smooth `sign = tanh(i/i_0)`, which avoids the chattering of the compensation due to the current ripple and the measurement noise near the zero crossings of the currents; `i_0` can be chosen to be about half the peak-to-peak current ripple.
- The synchronous machine is the PLECS permanent-magnet synchronous machine (`SynchronousMachinePars`) with the voltage-behind-reactance model (its rotor-reference-frame model, with controlled current sources, would toggle the diodes of a blocked leg at the zero crossings of its current) or a subsystem that looks like it (`SpatialSaturatedSynchronousMachinePars` with a GradNet current map with spatial harmonics): inside, a C-Script block computes the currents and the torque from the flux linkage, and they are injected with controlled current and torque sources.
- The induction machine is the PLECS squirrel-cage induction machine, parametrized as the T model with zero rotor leakage inductance, which is identical to the inverse-Γ model of *motulator*.
- The initial speed and angle of the machine (or of the inertia, and the angle sensor of the GradNet machine) are those of the mechanics of *motulator* (`mechanics.w_M0` and `mechanics.theta_M0` of the initialization commands).
- The DC bus is a DC voltage source (without a DC-bus model), a capacitor (`DCBus`), or a diode bridge fed by the grid with a DC-bus inductor and capacitor (`DiodeBridgeDCBus`, zero grid inductance). The DC-bus model feeds only the converter of the drive, and its capacitor voltage starts from the state of the model.
- The AC filter of the grid converter is an LCL filter or an L filter with its series resistance and the grid inductance (`LFilter`), with the grid as three AC voltage sources.
- The circuits are not grounded: as in the space-vector models of *motulator*, there is no zero-sequence path (grounding both the DC bus and the grid neutral would let the common-mode voltage of the converter drive a zero-sequence current).
- Voltmeters and ammeters are used only for the signals fed back to the control system. The AC voltages are measured line to line (u_ab and u_bc), as in practice. The other signals, e.g., the inductor currents shown in the scope, are measured with PLECS probes.
- A GradNet flux map of the control system is given as a struct in the initialization commands (`est_flux_map`).

## Agreement of the PLECS models with *motulator*

Maximum differences (PLECS − *motulator*) printed by the scripts, with *motulator* 0.15.0 and PLECS 5.0 (2026-10-18).
*motulator* uses the tolerances of 1e-9, and PLECS the variable-step Dormand–Prince solver with the relative tolerance of 1e-6 and the maximum step `T_s`.
After a change in the writers or the C port, regenerate the models by running the scripts and check that the differences stay at this level.

The differences are in SI units; relative to the signal magnitudes, they are about 1e-6 or below (e.g., 1e-3 W of 10 kW).
In `pmsyrm_6kw_gn_fvc.py`, the differences are larger (about 3e-6 relative to the torque and the current); they decrease with the tolerances of *motulator* (w_M 5.4e-6, tau_M 3.8e-5, and i_s_ab 1.3e-5 with 1e-10), but not with those of PLECS.
In `ipmsm_2kw_fvc.py --blocked`, the differences are at the level of the drive without the gate blocking, which verifies the standby of the control system with the measured converter voltages and the blocked converter, whose diodes conduct the decaying currents (*motulator* locates the transitions of the diode states as events).
In `im_2kw_dead_time_cvc.py`, the differences are due to the switching transients during blanking and at the zero crossings of the currents, which *motulator* does not model in detail.
*motulator* determines the state of a blanked leg and the voltage drop over the threshold voltage from the current direction at the latest switching instant, whereas in PLECS, the current of a blanked leg cannot cross zero, since its diode turns off, and the current of a leg stays at zero while the voltage across its devices is below their forward voltage.
At low speeds, this occurs often due to the current ripple near the zero crossings of the phase currents, and the sensorless low-speed operation amplifies the differences (e.g., 2.5 rad/s in the speed estimate during transients, compared with the speed reference of 7.9 rad/s).
Furthermore, at the first switching from zero currents, the blanked leg is open in PLECS.
The dead time causes most of the differences (w_M 0.77 and ctrl.w_M 2.4 with `U_TH = 1e-9`), and the single update, i.e., the twice higher switching frequency, makes them larger than with double update (w_M 0.23 and ctrl.w_M 1.3 with *motulator* 0.12.0, without the threshold voltage).
With `T_D = 1e-9` and `U_TH = 1e-9` in the script, the differences are at the level of the other examples (e.g., w_M 1.4e-6, i_s_ab 8.6e-6, ctrl.w_M 3.1e-6), which verifies the export of the dead time, the threshold voltage, the single update, and their compensation; with `T_D = 1e-9` and `U_TH = 1.0`, they are w_M 6.0e-3, i_s_ab 2.0e-2, and ctrl.w_M 6.2e-2.
With `--tanh` (`I_0 = 0.05` A, about half the peak-to-peak current ripple, which the single update halves from the 0.15–0.28 A of double update), the compensation is less sensitive to these differences near the zero crossings: the differences are smaller than with the signum function (e.g., w_M 0.36 and ctrl.w_M 2.0).
